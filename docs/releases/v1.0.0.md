# ProGuard 1.0.0

First public release. ProGuard is a Windows process manager in the spirit of Process Lasso: a Windows service keeps
the machine responsive by restraining processes that hog the CPU, applies the rules you set for individual programs,
and switches power plans to match what you are doing, while a WPF window shows what it is doing and lets you change it.

## Downloads

| File | What |
| --- | --- |
| `ProGuard-1.0.0-x64.msi` | Installer: engine as a Windows service, Start menu entry, optional start at sign-in |
| `ProGuard-1.0.0-portable-win-x64.zip` | Portable: unzip and run `Start ProGuard.cmd`, nothing installed |
| `SHA256SUMS.txt` | Checksums of both |

Both are self-contained x64 builds: no .NET install is needed.

## Features

**ProBalance.** Watches every process and, when the system is under load, temporarily lowers the priority of the
ones responsible so the program you are using stays responsive. Thresholds, sensitivity and the restore rules are
tunable. Optional restraint actions: restrain by affinity (or drop one core), lower I/O priority, switch the process to
efficiency mode, keep the priority class, pause ProBalance while the system is idle, and unpark every core while
anything is restrained. The foreground program and its children are never restrained; a session agent in each user
session tells the service which program that is.

**Rules.** Per-program rules the engine applies every time the program runs: CPU priority, I/O priority, memory
priority, affinity, CPU Sets, efficiency mode, priority boost, GPU priority and GPU preference; a CPU limit (either a
hard cap, or Process Lasso-style affinity reduction when the process stays above a threshold); startup boost; instance
limits; an instance balancer that spreads copies of a program over the cores; keep-running (restart it if it exits);
disallowed programs; a power plan to hold while the program runs; exclusion from ProBalance; and "set at launch", which
writes the priorities to Image File Execution Options so Windows applies them at process creation. Rules can be made
from the Processes page ("Always ..." in the process menu) or in the rule editor.

**Watchdog.** Rules that fire when a program's CPU, memory (working set or private bytes), running time or instance
count stays over a threshold for a set time: terminate it, restart it, set its priority, I/O priority or affinity (for
a while, then put it back), trim its working set, launch something, log an alert or show a notification. Each rule has
a cooldown.

**SmartTrim.** Trims the working set of processes over a size threshold while RAM load is high, on a schedule, with
exclusions. Optional standby-list purge when free RAM drops below a threshold (or only in Performance Mode) and file
cache purge. "Purge now" from the System page.

**Power.** Performance Mode switches to a high-performance plan while a listed program, a detected game or anything
started from a Steam library runs, and can hold the Windows 11 "Best performance" power mode too. IdleSaver switches
to a saving plan after a period without input and back when you return. The load switcher moves between two plans by
CPU load. A plan to apply when the engine starts. The engine arbitrates between them (Performance Mode > IdleSaver >
load switcher), logs every switch with its reason, and restores your plan at the next start if it died while holding
one.

**System.** System timer resolution held while the engine runs; the Windows 11 power mode; CPU tuning per power plan
(core parking, minimum and maximum processor state, boost mode, energy preference, parking thresholds, with presets and
revert); config profiles (named copies of all rules and settings), export and import; an activity log and an engine
log viewer with export.

**Processes page.** Live list with CPU, memory, priority, affinity and the rule in force; end a process or its tree,
set priority, affinity, I/O priority, memory priority, efficiency mode or a CPU limit for this run or always; make a
rule from a process. Changes made here are kept and re-applied.

**Standard users.** The window works without administrator rights for your own processes; anything that needs more
says so, with a "Restart as administrator" button. "Always start as administrator" is a per-user setting, and with it
on, start at sign-in uses a scheduled task so there is no UAC prompt.

**Languages.** The window comes in English, Spanish, German, French and Brazilian Portuguese, following Windows'
display language unless you pick one under System → General → Language. The translations are machine-assisted and not
yet reviewed by native speakers. Messages that come from the engine (its refusals, the activity log and the engine log)
are in English.

## Requirements

- 64-bit Windows 10 or 11.
- Nothing else: the engine, window and session agent are self-contained builds with .NET 10 (LTS) bundled.
- Administrator rights to install the MSI (the engine runs as a service). The portable zip runs without them, but then
  only manages your own programs.

## Install

Run `ProGuard-1.0.0-x64.msi`. It installs to `C:\Program Files\ProGuard`, registers and starts the `ProGuardEngine`
service, adds ProGuard to the Start menu and, by default, starts the tray icon when you sign in and asks for
administrator rights when the window opens (both can be changed on the System page or with the installer's options).

Silent install from an elevated prompt:

```
msiexec /i ProGuard-1.0.0-x64.msi /qn
```

Add `START_AT_SIGNIN=0` to skip the tray icon at sign-in, or `START_AS_ADMIN=0` so the window doesn't ask for
administrator rights each time it starts.

Settings, rules and logs live in `C:\ProgramData\ProGuard`.

## Upgrade

This is the first release, so there is nothing to upgrade from unless you installed a development build. Running the
1.0.0 MSI over any older MSI-installed build replaces it in one step: the service is stopped, the files are replaced,
the service starts again, and your settings, rules, logs and start-at-sign-in choice are kept. A service installed with
`install-service.ps1` is replaced the same way. Downgrades are refused.

## Uninstall

Settings > Apps > Installed apps > ProGuard > Uninstall, or:

```
msiexec /x ProGuard-1.0.0-x64.msi /qn
```

This stops and removes the service, closes ProGuard and deletes the program files. `C:\ProgramData\ProGuard` is kept;
add `REMOVE_DATA=1` to delete it too.

## Known limitations

- **Not code-signed.** Windows SmartScreen will warn about an unknown publisher: click "More info" > "Run anyway".
  Signing is wired into the build but off until there is a certificate.
- **x64 only.** No ARM64 or 32-bit build.
- **Don't run it alongside Process Lasso.** Both adjust the same processes and will fight. The installer warns if it
  finds Process Lasso but never changes or removes it.
- **Start at sign-in is per user.** The installer sets it for the user who runs the installer; other users turn it on
  from the System page.
- **Processor groups.** Machines with more than 64 logical processors are not specially handled.
- **IdleSaver** has no per-process exclusions or CPU-load gate yet, and the Windows 11 power mode is not part of the
  crash recovery that restores your power plan.
- **The portable build** keeps its settings in `C:\ProgramData\ProGuard`, the same place as the installed one. Use
  one or the other, not both at once.

## Reporting problems

Open an issue at https://github.com/ayrball/ProGuard/issues with `%LOCALAPPDATA%\ProGuard\ui-errors.log`, the files
in `C:\ProgramData\ProGuard\logs` and, for an installer problem, a log from `msiexec /i ProGuard-1.0.0-x64.msi /l*v install.log`.
